- **A CONTRL names the element in error the way the standard counts it**
  ([#208]). `UCD`'s and `UCI07`'s `0098`, *erroneous data element position in
  segment*, was one low: the standard says "the segment code and each
  following simple or composite data element defined in the segment
  description shall cause the count to be incremented. The segment tag has
  position number 1", and the mock was not counting the tag. So a bad
  `BGM03` was reported as element 3 rather than 4, and a bad `QTY01` as 1
  rather than 2. The two numbers beside it are unchanged and were already
  right: `0104` counts a composite's components from 1, with no tag to count,
  and `UCS`'s `0096` counts the `UNH` as segment 1. The buyer-side
  reconciliation note, which reports `0098` as it finds it, moves with this.
